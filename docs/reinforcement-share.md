# 增援占比

首页星球卡、星图面板和星球资料页在预测附近显示所需的全服在线兵力占比，
并列当前占比与差额。防守目标是截止前完成防守；普通解放战没有固定截止时间，
因此显示维持正向推进的门槛，不把抵消回血误称为已经足够获胜。

计算统一放在 `js/forecast.js`，沿用站内速率推演的效率常量 `K=90`：

```text
当前占比（%） = 当前星球玩家 / 全服在线玩家 × 100
每 1 个百分点占比的推进（%/h） = 全服在线玩家 × 影响系数 × K / 战役血量
防守所需速率 = (100 − 当前防守进度) / 剩余小时
防守所需占比 = 所需速率 / 每个百分点推进
解放持续推进门槛 = 抵抗度 / 每个百分点推进（必须严格超过）
```

防守血量取 `planet_events` 中对应入侵事件的 `maxHealth`，不使用己方星球本体血量。
全服在线总量与影响系数取同一份战况快照。全服人数变化时，若影响系数反向调整，
相同兵力占比与相同全服影响力预算会得到相同门槛。

存在近期实测防守速率时，优先以该速率除以当前兵力占比，估计每个百分点贡献并标注“实测”。
实测停滞或倒退无法提供正向效率，显示数据不足，不冒充正向模型。
缺少近期实测时，这是保持当前全服影响力预算和站内作战效率模型的条件估算，页面标注“推演”。
任务难度、完成效率、区域贡献及后续影响系数变化都可能改变结果；不把兵力占比单独当作胜利保证。
开战以来平均防守速率不用于反推当前兵力效率，避免把历史兵力投入与当前占比混配。

缺少全服总量、影响系数、抵抗度或事件血池时显示数据不足；零本地玩家仍可计算推演门槛。
超过 100% 的需求保留原值并标注当前效率下无法达成，不截断为看似可满足的 100%。
已完成或截止的战役不继续索要增援。显示门槛向上保留两位小数，差额单位为百分点。
