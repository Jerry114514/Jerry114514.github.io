# 七槽贡献比较与局部替换

用途：首次平衡抽取的内部重试。对外仍只输出七件装备，不显示分数、种子或搜索过程。纯随机与输出后的换装规则不变。

## 选择与准入

1. 先完整随机提出七槽候选，检查槽位、去重、锁定/排除、支援/背包互斥和单机甲限制。
2. 已合格就立即输出，不继续优化，不拒绝强配装。合格要求续航最终分至少55、其余五维至少60，以及双重甲、五洞、共享资源、近防安全全部通过。
3. 对不合格候选，轻量评价所有可替换槽位的边际贡献：临时关闭一件的贡献，保留完整七槽ID。主手、副手、手雷与四个战备均参与，锁定不动。优先保护移除后失去已有分数通过项/近防路线的装备，再比较实际缺口的变化；超过及格线的部分不产生保护或修复奖励。
4. 每个可替换槽位均匀随机试一件，再给低贡献组的至多两个槽位各试一件按缺口加权的不同替代品。低贡献并列者随机选，不偏向固定槽位。每件合法候选权重始终大于0，不按名字规定必带装备。
5. 对最多九个单件替换方案做轻量排序，分别从常驻短板、加值短板选择一个候选进入完整评价，同一候选覆盖两条方向时只验证一次；剩余名额取整套收益较好的候选，总计最多两套。任一真正合格即输出。均未合格时，从实际改善较好的至多两个档位中随机保留一套；无改善就整套重抽。保留改动后重新计算贡献，不能沿用旧的“第二弱槽位”。
6. 每个起始候选最多两轮，每轮最多两次完整试换检查；没有合格结果则重新完整随机抽取。不保存成功配装库或无界搜索历史。

## 轻量排序与完整评价

`previewAssessment`复用相同的分数汇总、人工校准、常驻续航和补给最终续航修正；跳过昂贵的共享资源、反重和拆洞模拟，不计未经执行证明的额外手雷补给加值。它只能返回 `RANKING_ONLY`，不能作为通过证明，也不把缺省物理项伪造为PASS。轻量排序可能漏掉好的候选，后续随机重启仍可探索它。

`evaluateAssessment`保留完整的原有物理账和六维门槛。只有其 `ESTIMATED_PASS && acceptance_ready` 才能输出。试换方案均单独通过互斥检查；中间评分可以跨过原先已通过的维度门槛，只要实际改良值上升且未通过的物理项数不增加。最终输出不能留缺口。

## 两类短板分开找

按逐维实际贡献方式拆分，而非简单将整件装备贴成蓝/红/绿：`routine[维度] = base_score`，`addition[维度] = auxiliary_bonus`。补给背包/补车引起的实际最终续航增量计入常驻层一次，已有加值不重复记账。

只针对整套仍有数值缺口的维度，分别找两层最低且当前候选可改善的项。分层收益取“该层增幅、该维最终缺口实际减少量、父配装剩余缺口”三者的非负最小值；层内增加40分但只填了10分缺口，只记10。最终缺口没有减少时，层间搬分不给奖励。物理失败单独处理，不虚构数值缺口。并列最低项可逐项改善；不能改善的结构性零不占用完整检查名额。两层各推荐一个候选，推荐顺序随机；不会因为常驻一次提升40分就自动排挤加值一次提升4分。两边不分别设60分线，整套已经覆盖的能力也不要求两层各自补齐。当前反重和拆迁按既有规则全部累加，常驻层这两项恒为0；它们不会占用常驻方向的试换名额，仍可由累加方向推荐。

这种分拆指导替换方向，轻量结果不能保证可兑现；最终仍执行同一整套准入检查。失败试换的保留仍先比较物理未通过数，再比较整套改良值，不将两层评分平均或相互替代。

## 改良值和采样提示

```text
T = 当前维度阈值（续航55，其余五维60）
D = Σ max(T - 当前维度最终分, 0)
U = -D
边际贡献 = 完整候选 U - 临时停用单件后的 U
```

六维统一只计算缺口，富余分不参与修复。某维从50到60或到100（及格60）都只填补10分；从60到100无收益。高分不能抵消另一项的新缺口。这个截断只用于修复排序，不修改装备分数或最终显示，也不拒绝原本随机抽中的强配装。未知分值只以0参与搜索提示，不会据此通过准入。物理未通过项减少优先于U改善，物理未通过数相同才比较U。

缺口加权候选使用1～4的有限权重：`1 + 3 × Σ min(该维缺口, 单件非负评分) / Σ缺口`；全部数值已过线时权重为1，不因尚有物理检查未通过而补造30分需求。单件超过剩余缺口的部分不再增加采样权重。该步骤只是粗略提示，实际替换收益由整套轻量/完整检查确认；补给设备仍以100作为单件提示并受到同样的缺口截断。上述只改变采样偏好，不改变任何单件评分、资源或通过条件；手雷/红绿的原始面板提示不充当最终配装收益。

该流程改变合格配装的分布，不再声称对所有合格组合均匀抽取。对每个初始合法父候选，最多4次完整试换和34次轻量评价（含父候选与停用比较），有限轮后重启。

## 时间、交互与状态保护

- 每个搜索step最多一次完整评价；在步骤之间让出执行权，保留Worker暂停、恢复、取消、重载隔离。没有新的联网或LLM调用。
- 资源执行器只对自身创建的私有状态优化复制：可变字段深拷贝，只追加的历史记录复制数组。保留全部资源/事件/时序与输出trace。公开ledger、补给、复装填API仍默认深拷贝，不能改动调用方状态。
- 小空间≤512组合仍按随机顺序精确枚举，避免锁定/小池无解时无限循环。
- `local_repair:false`仅供同模型A/B诊断，页面不新增模式。基准对照同样使用复制优化，避免把底层提速误算为搜索算法收益。
- 复用已有随机数、候选池、互斥和评价器，不引入求解器依赖。实现前对照了[OR-Tools的局部搜索与搜索限制说明](https://developers.google.com/optimization/routing/routing_options)，未复制其代码。

## 批量对照

运行 `node scripts/compare-loadout-local-repair.mjs --count 300 --start 240000`。同一模型、同一组种子，交替执行整套重抽与局部替换。初始种子相同，分支消耗随机数不同，后续候选不保证相同。调参试跑种子1101～1130，正式对照种子240000～240299，两组分离。另保留三槽短名单220000～220299与混合贡献排序230000～230299的对照。后者综合分88.64→89.07，均值差0.43的95%区间[-0.35,1.14]，尚未证明稳定提升；平均耗时424→434毫秒。这是用户要求分开两类短板之前的已完成基线，不混作本版结果。

主要强度指标是六维最终分各截到100后的平均值，另列逐维均值、最弱维度、覆盖与出现频次、耗时及失败。仅统计指标封顶，不修改准入或实际分数。报告保留逐套结果、来源哈希与配对均值差的bootstrap区间。这些属于当前模型的分数比较，不等于游戏实战强度认证。


常驻/加值的逐维均值和最低值也单独记录。加值续航等结构性零可能使该层最低值恒为0，不代表不合格。时间为已加载模型后的本机Node搜索耗时，不含网页下载、进程启动或网络。
