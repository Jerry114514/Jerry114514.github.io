# 站点战报

入口为 `HD2-Report/`，主站首页的「站点战报」按钮可进入。纯静态 HTML / CSS / JavaScript，可随现有 GitHub Pages 发布；无需本地日报程序或服务端截图服务。浏览器每分钟检查主站数据，隐藏页面暂停检查；刷新失败保留上次成功战报并显示错误。

页面提供主要指令、超级地球统计、敌方变种／特殊部队、阵营兵力、近 24 小时变化、DSS、热门战线和简中战争报告。支持复制完整文字与在浏览器导出 PNG 长图。网页与长图使用同一份战报模型，进度条、文本来源与预测口径保持一致。

热门战线按参战人数降序列前五颗。卡片下列出城市／工厂：中文名和类型、实际开放状态、解放进度、人数与未开放时的条件；已开放且有有效速率时补充净推进、抵抗度、完成／归零预计时长与依据。静态区域表和官中名读取主站 `tables/planet_regions.json`、`tables/planet_regions_zh.json`，开放判定复用 `js/regions.js`。不会因人数多而推定开放，未知状态明确保留；缺少工厂总血量不套用定居点血量。

每个城市／工厂还显示一次性回馈，复用主站 `HD2Regions.model().contribution`：区域总血量 × `damageMultiplier` ÷ 主星球总血量 × 100，单位为「个百分点」。防守战分母使用入侵事件血池，标为「主星球防守进度」。共用规则在血量或倍率使用默认值时会标记估算，缺少必要数据则显示未知。这是单次解放的回馈规则，已解放区域仍显示该数值供参考，不再叠加到当前星球进度或预测中；网页、复制文字与 PNG 同步。

## 数据与口径

- 当前状态读取 `HD2-Galatic_war-Map/data.json`，名称和效果说明读取主站 `tables/starmap.json`、`tables/hd2_variables.json`。
- 实测速率、指令和防御预测、特殊部队去重、DSS 捐赠、易主窗口复用现有共享模块。净推进无实测时采用主站的 `K=90` 推演，标出满血顶格、易主或无有效帧等原因；缺必要参数时标为未知。胜负与完成时间均为保持当前节奏的条件预测。
- 敌方变种／特殊部队延续原战报的交战范围：只统计当前战役或防守事件涉及的星球，不列非交战星球残留效果。根据主站变量表的敌方变种、特殊个体、军团与宗派类别筛选，排除设施、环境和友军火力；同星球的成对效果去重，按变种数量与星球中文名排序。防守星球仍在该列表中，不按超级地球属主误分为友军部队。
- 指令累计任务外推使用下达以来均速，近一小时节奏只作对照；守持任务显示截止时结算，不显示累计完成条。
- 解放净推进为负且当前解放度已知时，预计归零时长 = 当前解放度 ÷ 每小时倒退幅度，使用未四舍五入的净速率。页面、复制文字和长图均显示「预计归零」时长，前提为保持当前节奏；已为 0% 时显示「解放进度已归零」，僵持或数据不足时不编造倒计时。
- 每颗展示的星球均列出当前／总血量、相对百万血的血条倍数。解放战等效抵抗度 = 原抵抗度（%/小时）× 总血量 ÷ 1,000,000。防守战使用 `planet_events` 的战役血池，按入侵进度速率同样换算并标为「等效入侵压力」，与回血抵抗区分；缺少战役血池时不拿人类持有星球的本体血量替代，显示未知。网页、复制文字和 PNG 包含同一组数值。
- 超级地球统计来自主站 `war_stats.galaxy_stats`；战争天数按 `war.time` 计时，不把未知累计值显示为零。
- 24 小时对照由 `scripts/fetch_report_baseline.py` 从同一份主站 `data.json` 的 Git 历史取得，写入 `data/history/status_24h.json`。优先用可用本地 Git 历史，Actions 浅克隆时用同仓库的 GitHub API；不新增定时任务。页面校验基准与当前快照相隔 23–27 小时，标明实际基准时间；易主单列，总血量变化时不比较解放度，正常可比星球列出变化至少 3 个百分点、幅度最大的 6 颗。缺少有效基准时明确提示，补充 `ownership_history` 与在线人数历史中的已知记录。
- 有效基准和基准缺失两种分支均附「防守成功」，来自主站 `ownership_history.defenseEvents` 的近 24 小时实际记录，标明记录时间与实际覆盖范围；同属主的防守成功不会被快照易主对照漏掉，也不重复显示。过期、未来记录由主站共享选择模块排除；没有记录时明确说未记录到或来源不可用，不凭入侵事件消失推断胜利。
- 生态读取主站原有 `biome`，环境读取 `data/planet_environment.json`；采集器复用已经获取的 hd2dev 星球资料写入这个缓存，不额外请求星球接口。只保留生态与 `hazards` 环境事件，不把未知环境当成没有事件，也不凭生态猜测额外温度效果。中文名沿用原战报词表，缺少名称时提示待汉化。

## 配色与趋势

页面直接加载主站 `css/tokens.css`，共用黑底、面板、硬边框、琥珀强调色与阵营颜色；使用主站的 768px / 1024px 断点。长图从页面实际共享变量取色。

解放净推进为正时用蓝色右箭头，为负时用红色左箭头，停滞用黄色横线，未知为灰色。入侵战役攻守双方均为各自累计进度向右增长：守方蓝色，攻方红色。血量与等效抵抗尽量同一行；进度条下并列预测、敌方抵抗与潜兵推进，下一行合并生态、环境与速率依据。网页与长图均按可用宽度自动换行，保留完整文字，不省略字段；网页、文字和长图使用同一模型。

## 简体中文文本

优先读取 `data.json.news`、`data/translated/TransNews.json` 和 `data/translated/official_texts.json` 中实际存在的简中或现成汉化，按公告 ID 去重并标明「官方简中」「站点汉化」或「站点汉化 · 机翻」。不展示英文原文作为回退。

站点缺失的公告由 `scripts/fetch_report_dispatches.py` 在现有 `fetch-data.yml` 流程中补取 `https://api.helldivers2.dev/api/v2/dispatches`，请求 `Accept-Language: zh-CN`，并确认响应语言为 `zh-Hans` 或 `zh-CN`。接口即使返回简中语言标记，仍可能有英文条目，所以还须检查正文是否含中文。结果写入 `data/translated/report_dispatches_zh.json`，供浏览器同源读取，避免该接口未开放浏览器跨域访问的问题。两边均缺失时保留缺失状态，等待站点汉化；补取失败保留现有缓存。

```text
node scripts/tests/site-report-check.mjs
python -m unittest discover -s scripts/tests -p test_report_dispatches.py
python -m unittest discover -s scripts/tests -p test_report_data.py
```

另外在静态 HTTP 服务下检查桌面与手机页面、刷新失败提示、复制文字与 PNG 导出。不要以程序生成旧长图的本地接口验收本站页面。
