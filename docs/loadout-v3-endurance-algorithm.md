# 整套常驻续航算法

当前实现：`routine-primary-plus-backup-v1`。纯本地 JavaScript，运行时不使用大模型、Wiki、联网请求或随机评价。相同输入得到相同结果。

## 输入与范围

- 单枪续航 E 使用现有的一盒公共补给基线，人工校准优先，保持当前显示尺度。
- 常驻枪池只包含主手、副手、支援武器；C4背包按需要背包的支援武器纳入。明确保留给反重的装备退出该池。
- 近战武器单件续航统一为0，并完全退出续航汇总：不占主力、备用或平均分母，不产生人工续航加值。破门锤等有有限充能的近战也适用，原始充能/伤害资料保留供其他能力使用。
- 红绿战备、手雷、载具、自动背包和供给设备不进入常驻枪池。手雷继续单独按颗数评价。
- 人工整件设置为“套装加值”的装备退出普通枪池，在末尾加入一次。供给设备与手雷不借此重复计分；近战仍不参与续航加值。

## 主力与备用

每项职责适配度为 `clamp(当前能力分 / 60, 0, 1)`。

```text
q = 0.6 × 清杂适配度 + 0.3 × 近防适配度 + 0.1 × 反中适配度
V = q × 单枪续航E
常态续航 = min(100, 最高V + 0.35 × 其他V之和)
```

60%／30%／10%和备用35%是集中配置的工程初值，不是实测使用时间、命中率或新的反中硬门槛。主力是有效续航贡献最高的装备，不等于建议玩家始终拿着它。

新增低续航工具不会像均值模型那样扣分；两把能轮换作战的枪可以贡献备用价值。无限弹药武器仍需通过q折算，弱用途武器不会仅凭“无限”自动提供100分。

已知零值和未知分开。缺少续航或职责数据时保留已知部分作为下界；全部候选续航未知时结果为待补。未改变同一弹池不同模式不得重复相加的单件规则。

## 最后加入人工分和补给修正

1. 常态续航算完后，将明确的人工整件续航加值加入一次。沿用既有100以上显示压缩。
2. 按用户规则，携带补给背包或补给车时：`最终续航 = max(已有最终续航, 100)`。
3. 补包与补车同时携带仍只应用一次；已经超过100的分数不降低。单枪评分、人工零值和人工文件均不改变。

这是最终评分规则，不表示无限物资。真实资源账仍执行单人一盒公共补给、补包4盒及有限恢复、附近补车8盒；不计补车炮塔。互斥、20秒双重甲、五洞和共享弹药检查保持独立，100分不能绕过这些检查。

## 接口与状态

- 实现：[loadout-endurance.mjs](../shared/hd2-loadout/assessment-v2/loadout-endurance.mjs)。没有射击模拟或职责组合搜索。
- 接入：[evaluate.mjs](../shared/hd2-loadout/assessment-v2/evaluate.mjs) 返回 `endurance_assessment` 与 `dimensions.endurance.supply_adjustment`，保留每枪E、q、V以及主力/备用分解。
- 参数由构建器写入 `scenario.loadout_endurance`；最终分不会再重复重标尺度。
- 首次平衡抽取要求清杂、近防、反中、反重、续航、拆迁六项最终显示分全部达到60。续航先完成手工加值和补包/补车修正，再参与及格判定；不存在只显示100分却按补给前低分拒绝的情况。
- 分数达标仍须通过互斥、20秒双重甲、五洞、共享弹药与近防安全检查。纯随机不检查能力；输出后的换装不调用评价器，始终保留单机甲限制。模型及格不代表已完成游戏实战认证。
