# 整套常驻续航算法

当前实现：`routine-role-weighted-v2`（2026-11-03 用户确认）。纯本地 JavaScript，运行时不使用大模型、Wiki、联网请求或随机评价。相同输入得到相同结果。

## 输入与范围

- 单枪续航 E 使用现有的一盒公共补给基线，人工校准优先，保持当前显示尺度。
- 常驻枪池只包含主手、副手、支援武器；C4背包按需要背包的支援武器纳入。明确保留给反重的装备退出该池。
- 近战武器单件续航统一为0，并完全退出续航汇总：不占平均分母，不产生人工续航加值。破门锤等有有限充能的近战也适用，原始充能/伤害资料保留供其他能力使用。
- 红绿战备、手雷、载具、自动背包和供给设备不进入常驻枪池。手雷单件续航继续按颗数评价，作为下述加值的系数参与整套续航。
- 常驻武器即使人工设为“套装加值”，其续航仍作为单件 E 参与平均，不在末尾额外相加；其他五维仍沿用其人工模式。非持枪设备的显式人工加值规则不变。供给设备、手雷、近战不借此重复计分。

## 按职责分别加权

对清杂、近防、反中分别计算；A 是武器在该项职责上的能力分，使用当前显示尺度（含人工校准），不在60处截断。

```text
职责内武器权重 p(i,r) = A(i,r) / Σ武器 A(i,r)
枪械职责续航 E枪(r) = Σ武器 [p(i,r) × 单件续航 E(i)]
手雷补充 G(r) = 手雷该职责加值 × 手雷续航分 / 100
职责续航 E(r) = E枪(r) + G(r)
常态续航 = min(100, 0.50 × E(清杂) + 0.35 × E(近防) + 0.15 × E(反中))
```

50%／35%／15%为用户指定的最终合成比例。采用算术加权，不再保留旧的最高贡献与备用35%，也不采用调和平均或新增三个职责各自60分的门槛。能力评分比例用于推定分工，不是实测使用时间或命中率。

手雷不加入枪械平均的分母。加值使用清杂、近防、反中的当前单件显示值（清杂已包含既有投掷/补给修正），再各乘单件手雷续航分/100；不使用爆炸裸分、不把续航分本身直接相加，不使用反重/拆迁分来增加续航。例如手雷三项加值为20/10/30、续航50，则提供10/5/15，按50%/35%/15%合成为9点补充。手雷人工模式不会重复加入一次。烟雾等三项收益均0的手雷不会因为库存充足而提高续航。

手雷续航采用现有携带量加一盒公共补给基线（4携带＋补2对应60，补给效率权重较高）；补包/补车仍在末尾直接修正总分，评分不额外生成弹药。未知手雷加值另标缺口，仅计已知非负补充，不影响枪械分母。

新增低续航、具有该职责能力的武器可以拉低平均分，这是用户明确要求保留的行为；不会为避免下降而自动丢弃该武器。一把多用途武器可以参与三个职责，三项都只有它时，整套仍是它的单件续航分，不计三次库存。无限弹药武器也不能把同时携带的低续航武器从平均中抹掉；武器能力是否足够由其他维度与物理检查另行判断。

例如 A 的清杂/近防/反中为90/10/50，续航100；B为10/90/50，续航20。三个职责续航分别92、28、60，整套为64.8。不能把清杂92直接当作近防续航。装备顺序不影响结果。

已知能力0不占该职责分母；整项能力总和0时该项续航为0。正能力但续航未知时保留它的分母并将该项标为待补；能力未知意味着分母未知，该项也待补。未知项不静默丢弃来抬高平均，已知保守下界另列，不充当完整评分。未改变同一弹池不同模式不得重复相加的单件规则。

## 最后加入人工分和补给修正

1. 常驻武器的人工续航已在平均中计入；其他非持枪设备的显式人工续航加值沿用既有末尾处理及100以上显示压缩。
2. 按用户规则，携带补给背包或补给车时：`最终续航 = max(已有最终续航, 100)`。
3. 补包与补车同时携带仍只应用一次；已经超过100的分数不降低。单枪评分、人工零值和人工文件均不改变。

这是最终评分规则，不表示无限物资。真实资源账仍执行单人一盒公共补给、补包4盒及有限恢复、附近补车8盒；不计补车炮塔。互斥、20秒双重甲、五洞和共享弹药检查保持独立，100分不能绕过这些检查。

## 接口与状态

- 实现：[loadout-endurance.mjs](../shared/hd2-loadout/assessment-v2/loadout-endurance.mjs)。没有射击模拟或职责组合搜索。
- 接入：[evaluate.mjs](../shared/hd2-loadout/assessment-v2/evaluate.mjs) 返回 `endurance_assessment` 与 `dimensions.endurance.supply_adjustment`，保留每枪 E、三个职责能力分/占比、加权贡献，以及三项职责续航。
- 参数由构建器写入 `scenario.loadout_endurance`；最终分不会再重复重标尺度。
- 首次平衡抽取要求清杂、近防、反中、反重、续航、拆迁六项最终显示分全部达到60。续航先完成手工加值和补包/补车修正，再参与及格判定；不存在只显示100分却按补给前低分拒绝的情况。
- 分数达标仍须通过互斥、20秒双重甲、五洞、共享弹药与近防安全检查。纯随机不检查能力；输出后的换装不调用评价器，始终保留单机甲限制。模型及格不代表已完成游戏实战认证。

验收页包含当前保存数据下的示例组合和逐项分解；保存人工评分后刷新页面即可查看重算结果。
