03重要指令（Major Order）

数据来源

  • 进度：data.json → assignments（官方 API v2/Assignment/War/801）
  • 中文简报：major_order.translated_brief（翻译仓库官方 zh-Hans 采集）
  • 限定装备：major_order.tasks（按 setting.tasks[].valueTypes 解析：1=阵营3=数量5=装备 ID）

任务预测口径（js/forecast.js）

rate = current / 全程已历小时
projected = clamp((current + rate × 剩余小时) / goal × 100, 0, 100)
etaH = (goal - current) / rate
win = etaH ≤ remainingH
  • 速率来源优先级：实测帧全程均速 → 近 1 小时实测 → 推演均速
  • type 11（占领标记）不做线性外推（进度是 0/1 跳变）
  • type 13（驻守）只判当前是否满足条件

装备限定（限定装备官中名）

setting.tasks[].values[5]（装备 ID）
  → scripts/order_items_en.json（社区提取的官方英文串）
  → 站点图鉴 terms.json（官方简中名）
  → en_fallback（明确标记英文名回退）
  → unresolved（只保留 raw ID，不猜名）

为什么星区边界看起来像“类矩形”

游戏没有向公开接口提供可直接使用的星区多边形。当前星图不连接真实星球坐标生成自由多边形，而是把银河盘面切成一套极坐标格网，先判定每个格属于哪个星区，再沿不同星区之间的格边提取并集轮廓。

核心口径 一周 24 个楔形，每格 15°；径向 10 环，每环 0.1。整张图固定为 24 × 10 = 240 格。每条边只能是径向直线或同心弧，所以多格合并后会像几块大小不一、略带弧度的倾斜矩形。

这些边界是社区按星球分布推断出的可视化范围，不是官方行政区划。格网尺度直接决定观感：过粗会出现大台阶，过细又会失去游戏里的“大块领土”轮廓。

1. 输入：位置、星区与归属

输入用途是否影响几何
planets[].position归一化银河平面坐标 (x,y)，半径约 0–1是，决定星球所在格和空格补齐
secCnByPlanet(planet)按 starmap 权威映射取得中文星区名是，格子的归属标签
currentOwner星区底色、势力统计否，换阵营不改边界形状

2. 把星球投到 15° × 0.1 的格网

角度从屏幕上方向开始编号，同时把右手系坐标旋转 90°，使编号方向与站内星图一致。格键写作 w:r：

θ  = normalize(atan2(y, x) + 90°)
w  = floor(θ / 15°)             // 0..23
r  = floor(hypot(x, y) × 10)    // 0..9
id = w + ":" + r

w=23 的下一个角向格回到 w=0，因此所有角向邻接都做 24 取模。半径两端会钳制到合法范围，避免浮点误差产生 r=-1 或 r=10。

3. 用星球决定每格归属

  1. 星球认领自己的格：按上式计算 cellId，把星球加入该格。
  2. 一格多星时投票：统计格内星球所属星区，星区数量最多者获胜。
  3. 票数相同看距离：比较星球到格心的欧氏距离，最近的星球所属星区获胜。这样可避免“这颗星球长在别人家色块里”。
  4. 空格寻找最近星球：对没有星球的格，以其格心为查询点，选择全图欧氏距离最近的星球，并继承该星球的星区。

完成后得到完整的 cellOwner[w:r]。当前数据里 240 格全部有归属，没有未分配空洞；星区边界只能落在格线上，不会穿过某一格。

底色不是边界 星区是否存在敌占星球只影响填充颜色。即使整片星区都归超级地球，边界线仍照常存在；几何与当前阵营是两套独立状态。

4. 从 240 个格中提取共享边

若逐格描边，每格的四个边都会重复绘制，半透明填充下会出现发丝缝和叠色。现行实现把整个格网看成一张平面图：

  1. 对每个格检查内弧、外弧、顺时针径向边、逆时针径向边。
  2. 只有“当前格星区 ≠ 邻格星区”的边才进入轮廓。
  3. 轮廓边按逆时针方向登记：内弧沿 +w、右径向沿 +r、外弧沿 -w、左径向沿 -r。
  4. 角点记为 w:r；全部轮廓边先合并成无向边表。
  5. 在度数不等于 2 的 junction 处切链。两个 junction 之间的连续边形成一条共享边链，相邻星区以正、反方向共同引用。

这一步同时处理两个容易出错的情况：相邻星区必须得到完全相同的折线，不能各自简化；两个格只接触一个角点时，该角可能“2 进 2 出”，所以程序保存的是有向边列表，而不是每个角点的唯一后继。

5. 只合并同向共线点，保留直角拐点

早期版本尝试用 Douglas–Peucker 把细密台阶压成直线，边界会更平滑，但会变成任意角度的斜多边形，失去游戏观感。现行算法只删除连续、同向且叉积近似为零的中间点：

  • 径向边继续是直线；
  • 同心弧按 1.25° 一段取样，避免长弧退化成一根弦；
  • 所有 90° 型拐点保留，形状严格留在原始格网坐标上。

共享链先统一简化，再供两侧星区共同使用，所以相邻填充之间不会因为两条不同的简化折线而裂开。

6. 走环、识别洞并输出 MultiPolygon

  1. 从任一未使用的有向边开始；走到共享链时，一次性复用整条链的折线。
  2. 在 junction 选择“最左转”出口。这是平面图追踪面的标准做法，也能把对角相接的两格拆成两个独立面。
  3. 回到起始边视为闭合。步数上限 5000 防止异常数据卡死；未能闭合的环会被跳过并在控制台告警。
  4. 用有符号面积区分外环和内环（洞）。外环、内环分别整理成 RFC 7946 要求的绕向。
  5. 若某星区被另一星区完整包围，以射线法做点在多边形内测试，寻找最小宿主外环并挂入对应洞。
  6. 每个星区输出一个 GeoJSON Feature，几何为 MultiPolygon，属性包括星区名、星球数、描边色和底色。

填充与描边最终复用同一份 GeoJSON，不需要为每格单独建面。这样既消除格间缝，也降低重复面片数量和 GPU 绘制开销。

7. 复杂度、稳定性与边界

归属计算空格最近星球需要约 240 × N 次距离比较，N 为当前星球数。
几何稳定星球坐标和星区映射不变时，边界是确定性的；只有阵营颜色会随实时战况变化。
重算时机修改 WED/RING、新增星球或修正星区映射后才需要重新生成。

它是“像游戏”的推断边界，而不是官方数据解密结果。若按真实世界法律、剧情或游戏后台区划理解，会得到错误结论；本页描述的是当前 galaxy-map-v2.html 实际执行的渲染算法。

06下属区域（城市 / 超大型工厂）

数据源

  • 静态表 tables/planet_regions.json（84 颗有城市/工厂的星球，来自 wiki Lua 模块）
  • 中文名 tables/planet_regions_zh.json（游戏内文本解包的官方简中）
  • 运行时 data.json → planets[].regions[]（官方实时数据）

区域速率：实测优先（data/recent/planet_regions.json 帧差分），推演兜底（区域玩家 × impactMultiplier × K ÷ 区域血量 − 区域抵抗度）。

区域规则（js/regions.js）

  • 开放条件 = 入侵进度 ≥ (1 − availabilityFactor) × 100 或 主星球解放 ≥ 阈值
  • 解放贡献 = 区域满血 × damageMultiplier / 母星球血池 × 100（个百分点）

07解放速率与实测帧

全站统一口径实测优先、推演兜底。

实测帧

  • 来源：data/recent/（CDN 15 分钟一帧，由采集脚本落盘）
  • 文件：index.json（清单）、planet_<idx>.json（单星球血量帧）、assignments.json（MO 进度帧）、planet_regions.json（区域帧）
  • 断更保护：清单生成时间超 3 小时 → 整块停用实测，自动回退推演

差分公式

实测净推进 %/h = −(末帧血量 − 首帧血量) ÷ 满血 × 100 ÷ 帧间隔小时
施加 / 纯产出   = 实测净推进 + 抵抗度
等效抵抗度     = regenPerSecond × 3600 ÷ 1,000,000 × 100（100 万血基准）

满血顶格拒绝：窗口首尾帧都 ≥ 满血（容差 0.05%）时不产出实测（Δ=0 不代表净速率为 0，必须交推演兜底）。

易主拒绝：窗口内星球归属发生变化时不产出实测。

13弹道模拟器

文件：HD2_Ballistics/（纯前端离线，无第三方依赖）

作者：@Darctor · 哔哩哔哩

物理模型（ballistics.js）

  • 各向同性二次空气阻力：a_drag = -K·|v|·v，K = 0.5·ρ·Cd·A/m
  • 恒定重力（可乘 gravity_multiplier）
  • 伤害公式：伤害比例 = 25% + 75%·(v/v_config)²
  • 速度继承：发射者移动矢量按世界坐标（X前/Y上/Z右）合成到出膛初速

武器目录（HD2_Ballistics/data/equipment_catalog.json）

  • 上游来源：Darctor/Helldivers2_RawData（按 HEAD SHA 绑定 URL）
  • 同步频率：每天（sync-ballistics-catalog.yml）
  • 关联规则：Wiki 装备名 → PWC 组件名（精确归一→标点归一）→ 射弹（组件直配→伤害+数值确定性搜索）

预算上限：MAX_TOTAL_STEPS=250000（积分步数）、MAX_ANGLE_SAMPLES=3600（扫描采样数），超限直接报错。
